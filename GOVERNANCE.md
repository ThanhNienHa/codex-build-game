# Governance

The project currently uses a maintainer-led model.

- Maintainers decide scope, releases, and supported engine workflows.
- Material changes should begin with a public issue and concrete acceptance criteria.
- Pull requests require passing validation and review of licensing, safety, and workflow impact.
- Contributors with sustained, high-quality participation may be invited as maintainers.
- Maintainer access should follow least privilege and use protected branches once hosted publicly.

Decisions that affect contributor rights, licensing, security disclosure, or project direction must be documented publicly unless confidentiality is required for security.
